When the Jacobian Is Dense but the Program Is Not

In machine learning, automatic differentiation is mostly used for products with the Jacobian: the gradient of a loss is a single vector-Jacobian product, and training never forms the Jacobian itself. Many methods in scientific computing need the matrix. Newton’s method for a nonlinear system 𝐹(𝑥)=0, at the heart of implicit time stepping for stiff differential equations and of steady-state solvers for discretized partial differential equations, factorizes the Jacobian in every step, and solvers for constrained optimization, such as Ipopt [1] and Uno [2], take the Jacobian of the constraints and the Hessian of the Lagrangian as matrices. These Jacobians are large, with thousands to millions of unknowns, but more often than not sparse, since each equation involves only a few unknowns.

An Illustrated Guide to Automatic Sparse Differentiation [3] explains how standard automatic differentiation tools can be used to compute a sparse Jacobian at a fraction of the cost of a dense one. The idea is fairly simple: first detect which entries can be nonzero, group the columns (or rows) that never share a row (or column), and compute Jacobian-vector (or vector-Jacobian) products in order to generate the sparse Jacobian.11 The grouping is for efficiency: all columns of a group are computed by a single Jacobian-vector product, and all rows of a group by a single vector-Jacobian product. In Backpropagation as a Linear Solve we derived that the Jacobian of any computation can be computed as

𝐽=𝑃𝐿−1𝑀⊤,

(1)

where 𝑃, 𝑀, 𝐿 are matrices which more often than not are sparse and with 𝐿 further being unit lower triangular. Even when 𝐽 is dense, products with it are cheap: 𝐽𝑣=𝑃(𝐿−1(𝑀⊤𝑣)) is evaluated from right to left, with one forward substitution in the sparse, unit lower triangular 𝐿, at about the cost of running the program.22 Likewise for the transpose: 𝐽⊤𝑤=𝑀(𝐿−⊤(𝑃⊤𝑤)) needs one backward substitution in the unit upper triangular 𝐿⊤, which is reverse mode. What a dense 𝐽 makes expensive is forming it, or solving with it.

This post asks what the matrices 𝐿, 𝑀, and 𝑃 add to the understanding of the Jacobian. The answer in short is that they pay off when 𝐿 is sparse but 𝐿−1 is dense, resulting in a dense Jacobian 𝐽 (e.g., Example 1).

1. From program to matrices

We can create 𝐿, 𝑀, and 𝑃 automatically by recording the program. A tape stores the partial derivatives of every operation, evaluated as the program runs; the intermediate values are only needed during the run, to compute those partial derivatives and the outputs. The tape of this post is deliberately small. A Tracked number holds a value and the index of its node. Arithmetic on Tracked numbers is overloaded, as for dual numbers: a * b computes the product, gives it the next node index, and stores its partial derivatives, b with respect to a and a with respect to b, as entries of 𝐿 or 𝑀⊤, depending on whether a and b are nodes or inputs. The function trace runs 𝑓 on Tracked inputs and returns 𝑓(𝑥) together with the sparse matrices 𝐿, 𝑀⊤, and 𝑃.

With the matrices at hand, the Jacobian itself is a triangular solve with a sparse right-hand side, 𝐽=𝑃(𝐿−1𝑀⊤). Column 𝑘 of 𝐿−1𝑀⊤ is nonzero only at the intermediate variables that depend on 𝑥𝑘, and a sparse triangular solve finds those by a search through the graph of 𝐿 before it does any arithmetic. SparseSparse.jl does this when both sides of \ are sparse, whereas the standard library returns a dense matrix.

2. The augmented system

While both the Bratu and the heating residual (Example 3) in Code 2 give sparse 𝑃, 𝐿, and 𝑀, only the Bratu Jacobian is sparse. The cumulative sum of Example 1 already showed how this can happen: a sparse 𝐿 can have a dense inverse, in which case sparse differentiation cannot help. For products, a dense 𝐽 is no problem, since 𝐽𝑣=𝑃(𝐿−1(𝑀⊤𝑣)) costs one forward substitution. Newton’s method for 𝐹(𝑥)=0, however, needs a solve, 𝐽Δ=𝐹(𝑥), in every step, and with a dense 𝐽 that means forming 𝐽 and factorizing it, at a cost of order 𝑛3. The cumulative sum also hinted at the way around this: given 𝑃, 𝐿, and 𝑀, the solve can be written as one sparse augmented system,

𝐽Δ=𝐹(𝑥)⟺[𝐿−𝑀⊤𝑃0]⏟𝐴[𝑧Δ]=[0𝐹(𝑥)],

(11)

whose first block row gives 𝑧=𝐿−1𝑀⊤Δ and second 𝑃𝑧=𝐽Δ=𝐹(𝑥). Newton’s method can therefore solve with the sparse 𝐴, whose unknowns are 𝑧 and the step Δ, instead of with the dense 𝐽.55 The same factorization of 𝐴 also solves with 𝐽⊤, as in adjoint methods: 𝐽⊤𝑤=𝑔 is [𝐿⊤𝑃⊤−𝑀0][𝜆𝑤]=[0𝑔], the system with 𝐴⊤.

3. Lifting

This could seem like the end for using standard AD software for getting the sparse augmented Jacobian, however that is not true. A simple technique called Lifting [5] instead rewrites the program, so that the intermediate variables become unknowns. That is, the lifted program returns both 𝑢 and 𝑓(𝑥), and the forward relation and the outputs become equations. Said differently: The lifted program has a Jacobian that is exactly the augmented matrix 𝐴 of (11) 99 𝐺(𝑢,𝑥)=(0,𝑓(𝑥)) holds only at 𝑢=𝑢(𝑥), the values the program computes; for other 𝑢, the first block measures how far 𝑢 is from satisfying the forward relation.

𝐺(𝑢,𝑥)=[𝑢𝑃𝑢]−[Φ(𝑢,𝑥)0],𝐺(𝑢(𝑥),𝑥)=[0𝑓(𝑥)],𝜕𝐺𝜕(𝑢,𝑥)=[𝐼−𝜕Φ𝜕𝑢−𝜕Φ𝜕𝑥𝑃0]=[𝐿−𝑀⊤𝑃0],

(15)

Now the Jacobian of 𝐺 is sparse, even when 𝐿−1 is dense. That means that tools such that DifferentiationInterface.jl or adsex can be used to extract the sparse Jacobian. By hand, lifting every operation would mean rewriting the whole program as equations, so in practice only the few intermediate variables that couple many others are lifted, such as the integral in the heating problem.

4. Summary

Every Jacobian of a program is the product 𝐽=𝑃𝐿−1𝑀⊤. Even when the three matrices are sparse, the inverse 𝐿−1 can be dense, resulting in a dense Jacobian. Sparse differentiation pays off when 𝐽 is sparse, but not when it is dense. In this case actually knowing the structure of the Jacobian can be useful. Either directly knowing 𝑃, 𝐿, and 𝑀 gives us a sparse representation of the Jacobian, or lifting the program to expose intermediate variables gives a sparse Jacobian which can be connected to the original dense Jacobian through a Schur complement.1111 Eliminating the intermediate variables from the lifted Jacobian leaves the Schur complement of the upper-left block 𝐿 in [𝐿−𝑀⊤𝑃0], which is 0−𝑃𝐿−1(−𝑀⊤)=𝑃𝐿−1𝑀⊤=𝐽.
